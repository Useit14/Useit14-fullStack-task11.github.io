Что обычно даёт AMP: быстрее первая отрисовка (FCP/LCP), меньше блокирующего JS (TBT ≈ 0), жёсткие ограничения на CSS/JS, кеширование через AMP Cache при переходе из Google. Минусы — ограничения на интерактив и размер amp-custom CSS (≤ 75 КБ).

Выводы по замерам

Mobile — AMP заметно выигрывает. Общая оценка Performance выросла с 94 до 99. Ключевой вклад — LCP: 3.2 с → 2.0 с (улучшение на 1.2 с, ~38%). Это главная метрика Core Web Vitals: обычная версия выходит за «хороший» порог 2.5 с, AMP — укладывается. FCP, TBT и CLS не изменились (0.8 с, 0 мс, 0.001) — обе версии уже хороши по этим метрикам. Единственный проигрыш AMP — Speed Index: 0.8 → 1.2 с. Причина в обязательном рантайме (v0.js + скрипты amp-carousel/amp-sidebar): страница дольше «дособирается» визуально, хотя первый контент и главный блок появляются не хуже. На общую оценку это влияет слабее, чем LCP, поэтому итог всё равно в пользу AMP.
Desktop — паритет. Обе версии упираются в 100 баллов. По FCP/LCP/Speed Index AMP чуть медленнее (0.2 → 0.3 с, 0.6 → 0.7 с, 0.4 → 0.5 с) — снова за счёт рантайма, но на быстром десктопном соединении и мощном CPU это не влияет на оценку. CLS у AMP даже лучше (0.001 → 0), но разница в пределах погрешности измерения.
Общий вывод. На мобильных AMP даёт реальный выигрыш — прежде всего за счёт LCP, то есть ускорения загрузки главного контента (в нашем случае — фонового изображения и крупного заголовка hero-блока). Это ожидаемо: AMP-компоненты (amp-img, amp-carousel) применяют lazy-load и приоритизацию «из коробки», а жёсткие ограничения не дают странице «потяжелеть» из-за сторонних скриптов. На десктопе разницы нет, потому что обе версии уже быстрые и упираются в потолок оценки. Плата за выигрыш — рост Speed Index на mobile и небольшие задержки FCP/LCP/SI на desktop из-за обязательного AMP-рантайма, а также ограничения на интерактив и лимит amp-custom CSS (≤ 75 КБ). Для контентной/лендинговой страницы, которая должна быстро открываться с телефона, обмен оправдан; для интерактивного SPA — скорее нет.
